# Лабораторна робота 2: Система Управління Бібліотекою

## Опис
Застосунок на TypeScript для управління книжковим фондом бібліотеки, позичання книг та обліку користувачів.

---

## Webpack vs Vite

В рамках розробки даного проєкту було проведено практичне порівняння двох систем збірки — **Webpack** та **Vite**.

1. Швидкість старту Dev-сервера та HMR
Webpack: Працює за класичною схемою — перед запуском webpack-dev-server збирає весь проєкт у пам'яті (компілює TypeScript, транспілює стилі, зв'язує модулі). На невеликих проєктах це займає кілька секунд, однак із ростом кодової бази час холодного старту помітно зростає. HMR (Hot Module Replacement) оновлює модулі швидко, але відчувається затримка на повторну перезбірку залежностей.

Vite: Використовує нативні ES-модулі (ESM) браузера під час розробки та попереднє бандлення залежностей через esbuild (написаний на Go). Це забезпечує майже миттєвий запуск dev-сервера (< 200 мс), незалежно від обсягу коду. HMR працює точково — перепідвантажується лише змінений модуль, що робить зворотний зв'язок під час верстки та логіки миттєвим.

2. Час і складність налаштування конфігурації
Webpack (webpack.config.js): Вимагає явного визначення кожної сутності. Для роботи TypeScript та стилів необхідно вручну підключати ланцюжки лоадерів (ts-loader, style-loader, css-loader, sass-loader), а також плагіни для обробки HTML (HtmlWebpackPlugin). Конфігурація виходить об'ємною, декларативною та вимагає розуміння того, як лоадери передають дані один одному.

Vite (vite.config.ts): Надає підхід "out-of-the-box". TypeScript розпізнається та обробляється за замовчуванням без додаткових лоадерів. Підключення стилів (SASS/Tailwind/Bootstrap) вимагає мінімальних дій (часто лише встановлення препроцесора чи пост-обробника). Конфігураційний файл виходить лаконічним, а наявність першокласної підтримки TypeScript у самому vite.config.ts робить автодоповнення та типізацію зручною.

3. Розмір та швидкість продакшн-збірки
Webpack: Використовує власний механізм бандлінгу. Отримані файли містять службовий runtime-код Webpack для імпорту модулів. Збірка потребує детальнішого налаштування Optimization (Minification, Tree Shaking, SplitChunks), щоб досягти оптимального розміру.

Vite: Для продакшн-збірки використовує Rollup. Це дозволяє генерувати надзвичайно чистий, оптимізований bundle з високоефективним Tree Shaking та автоматичним розділенням коду (Code Splitting). Розмір підсумкових ассетів виявився дещо меншим, а сама збірка через npm run build виконується швидше.

4. Інтеграція UI-фреймворків, TS-лоадерів та екосистема
Підключення UI та TS: У Webpack комбінація ts-loader та CSS-лоадерів вимагає детальної настройки module.rules. У Vite достатньо імпортувати CSS/SCSS або модуль UI-фреймворку безпосередньо в .ts файл точки входу, і інструмент автоматично зкомпілює його.

Екосистема плагінів: Webpack володіє величезною, перевіреною роками екосистемою, де можна знайти вирішення для будь-якої нестандартної задачі. Проте екосистема Vite / Rollup розвивається винятково стрімко і наразі покриває 99% потреб сучасного веб-розробника, пропонуючи простіший API для створення власних плагінів.

### Висновок:
Для невеликих та середніх SPA-проєктів на TypeScript **Vite демонструє суттєву перевагу**: розробка починається миттєво, конфігураційний файл `vite.config.ts` займає лише 10-15 рядків, а швидкість фідбеку при зміні коду значно вища порівняно з Webpack.
